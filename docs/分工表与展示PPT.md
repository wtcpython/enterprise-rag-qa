## 二、 5 分钟展示答辩 PPT 逐页大纲（严格对齐 1 + 2 + 1 + 1 分钟节奏）

### Slide 1：封面、核心量化成果与 5 分钟答辩议程
- **项目定位**：面向企业私有制度与技术文档的**强溯源、可拒答、可观测**知识库问答系统（RAG）。
- **核心实测指标概览**（源自 `outputs/*.json`）：
  - **知识库规模与增量索引**：4 份多格式制度文档（`.md / .docx / .pdf / .txt`），主索引切分为 **20 Chunks**（`chunk_size=400, overlap=80`），MD5 增量索引跳过未改文档耗时 `< 5ms`；
  - **纯检索召回率**：22 道有答案题 `Hit@3 = 100%`、`Recall@3 = 96.82%`、`Recall@5 = 100%`、`MRR@5 = 0.9773`；
  - **端到端生成质量**：有答案题整体正确率从基线 `96.82%` 提升至 **`100.00%`**（跨段综合题从 `93.00%` 提升至 **`100.00%`**），逐条声明忠实度达 **`100.00%`**；
  - **无答案安全边界**：校准距离阈值 `0.44` 叠加 LLM Rerank 协同判定后，8 道无答案题 **100% 路由至 `refusal` 路径**，有答案题被误拒数为 **0 题**。

### Slide 2：第 1 分钟 — 需求背景、系统总体架构与切分/增量索引设计（0:00—1:00）
1. **离线解析清洗与增量索引流（`app/parser.py` & `app/indexer.py`）**：
   - **多格式统一解析与针对性清洗**：基于 `MarkItDown` 解析 4 种格式，针对无表格线 PDF 被 `pdfplumber` 误加伪表格竖线（`|   | 12 | | 位`）的问题编写清洗算子，使有答案题 `Hit@3` 从 `90.91%` 跃升至 `100%`；
   - **真实滑动窗口语义切分**：`chunk_size=400, overlap=80`，按标题/段落/句子边界切分并精确回溯 80 字重叠，保护跨段前提与 Markdown 表头完整性；
   - **元数据与增量索引**：每个 Chunk 注入 `source / chunk_id / chunk_index / page / section / file_md5`；通过 `hashlib.file_digest(f, "md5")` 实现文件级增量跳过与重入库自动清理旧块。
2. **在线双层检索与四级安全生成流（`app/retriever.py` & `app/generator.py`）**：
   - **严格分离 `docs` 与 `contexts`**：本地 `models/Qwen3-Embedding-0.6B` 稠密检索 + `rjieba/bm25s` 稀疏检索经 RRF 融合产出全量候选 `docs` (`recall_k=8`) $\rightarrow$ 经 `clean_json_text` 修复后的 LLM Rerank 精选 `contexts` (`top_k=4`) 送入生成模型；
   - **四级安全路由与缓存**：结合校准阈值（`refusal=0.44, fallback=0.36`）与 Rerank 高分豁免（$\ge 7.0$）路由至 `normal / fallback / refusal / error`；内置 `OrderedDict` LRU 问答缓存。

### Slide 6：第 5 分钟（上）— 4 道典型真实失败案例深度剖析（4:00—4:35）
1. **案例 1 [`Q15` · 多跳前提截断]**：询问“P7 专家去武汉住 1 晚花 690 元且只开普票，是否需超标特批？最终报销多少？”。在 `top_k=3` 下，前 3 个片段被职级表格与发票折算条款占据，排在第 4 位的 `chunk_000`（武汉属二类城市）被截断，导致模型无法判断超标比例（得分 `0.50`）。在 `optimized` 下扩展 `recall_k=8 -> contexts=4` 后 4 个片段全入列，模型准确算出 $(690-600)\div 600 = 15\% \le 20\%$ 需二级部门总监特批，得分升至 `1.00`。
2. **案例 2 [`Q07` & `Q01` · 单一硬阈值同义异形误拒]**：`Q07` 用口语询问“账号密码最小长度”，而原文为公文术语“强口令策略”，余弦距离 `0.4742 > 0.44`（`Q01` 距离 `0.4574 > 0.44`），在 `threshold_tuned` 与 `hybrid` 下被误拒（得分 `0.0`）。在 `optimized` 下经 LLM Rerank 复核打出 `10.0` 分（$\ge 7.0$）成功豁免误拒并转入 `fallback`，恢复 `1.00` 满分。
3. **案例 3 [`Q26` & `Q28` · 高相似伪装无答案题]**：`Q28` 询问“星云智联 V4.2 企业版私有化年度订阅报价”，因共享大量专有前缀，向量距离低至 `0.3967`。`baseline` 阈值 `0.55` 下漏过检索防线白白消耗生成 Token；`optimized` 模式下由 LLM Rerank 识别候选块无报价信息并打出 $\le 2.5$ 低分，在进入生成前 100% 拦截至 `path=refusal`。
4. **案例 4 [入库期隐患 · PDF 伪表格竖线噪声]**：`pdfplumber` 将 PDF 对齐空格误判为表格列生成 `|  | 12 | | 位`，导致 `Hit@3` 仅 `90.91%`。编写 `_clean_text` 剥离伪竖线后，块数从 24 收敛至 20，`Hit@3` 与 `Recall@5` 均提升至 `100%`。

### Slide 7：第 5 分钟（下）— 优化工程代价、适用边界与团队分工表（4:35—5:00）
- **优化的真实工程代价（Trade-offs）**：
  - **Token 代价**：引入远端 LLM Rerank 使单题系统总平均 Token 从 `hybrid` 的 `1020.3` 增至 `3274.2`（增加 **2.21 倍**，其中 Rerank 平均消耗 `2022.4` Tokens/题）；
  - **延迟代价**：串行执行一次 LLM Rerank 使平均延迟从 `threshold_tuned` 的 `1738.1 ms` 上升至 `2948.0 ms`（P95 为 `5104 ms`）。
- **场景适用边界结论**：
  - **简单事实与 FAQ 查询**：仅需开启 `Vector + BM25S 混合检索 + 适度阈值 (0.46)`，在 ~`1020` Tokens 开销下即可获得高准确率；
  - **复杂跨段计算与高合规审计场景**：必须开启 `真实 Overlap + 较大 Recall-K + Rerank 重排豁免`，以约 2.2 倍 Token 成本换取 100% 多跳完整性与零误拒。
- **后续演进计划**：使用本地轻量级 Cross-Encoder（`bge-reranker-v2-m3` / `Qwen3-Reranker-0.6B`）替代远端 LLM Rerank，将重排 Token 降至 0、重排延迟压缩至 `< 80ms`。
