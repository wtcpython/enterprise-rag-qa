【星云智联（Nebula-AI）企业知识引擎 V4.2 产品技术支持与运维 FAQ】
文档编号：PRD-FAQ-2026-04

Q1: 星云智联企业知识引擎 V4.2 私有化部署的最低硬件配置要求是什么？
A1: 私有化标准版最低硬件配置要求如下：
- CPU：至少 16 核 x86_64 处理器（推荐 Intel Xeon Gold 6330 或同级鲲鹏 920）；
- 内存（RAM）：最低 64 GB（若开启本地重排与本地向量模型常驻，推荐 128 GB）；
- GPU 加速卡：最低 1 张 NVIDIA L20（48GB 显存）或 2 张 NVIDIA RTX 4090（24GB 显存），显存总计不得低于 24 GB；
- 存储空间：系统盘 200 GB SSD，数据盘至少 1 TB NVMe SSD（IOPS ≥ 30000）；
- 操作系统：Ubuntu 22.04 LTS 或银河麒麟 V10 SP2。

Q2: 调用知识检索或问答 API 时返回错误码 ERR-4029 是什么原因？如何解决？
A2: 错误码 `ERR-4029` 表示“租户级向量与大模型并发令牌桶限流触发（Tenant Rate Limit Exceeded）”。
触发原因：标准企业版单个租户默认 API 并发上限为 30 QPS（每分钟最大 Token 吞吐量 TPM 上限为 120,000 Tokens）。当突发流量超过该阈值时，网关会拦截请求并返回 HTTP 429 及业务错误码 ERR-4029。
排查与解决步骤：
1. 在客户端 SDK 中开启指数退避重试（建议初始退避 500ms，最大重试 3 次）；
2. 登录星云管理后台“系统设置 -> 流量配额”，检查是否存在异常脚本高频刷接口；
3. 如属正常业务高峰，可联系管理员在 `nebula-gateway.yaml` 中将 `tenant_max_qps` 调高至 80 QPS（需确保后端 GPU 节点数 ≥ 2）。

Q3: 增量建索引任务卡死并报错 ERR-5003（Chroma Lock Timeout）该如何处理？
A3: 错误码 `ERR-5003` 表示向量数据库写锁超时（默认等待锁超时时间为 45 秒）。
常见原因：上一次批量全量重建索引（rebuild）进程被非正常强制杀死（SIGKILL），导致持久化目录下的 SQLite 预写日志锁未释放，或同时有多个 Worker 进程并发写入同一个 Collection。
解决步骤：
1. 停止当前离线索引 Worker 容器：`docker compose restart nebula-indexer`；
2. 检查持久化目录是否存在残留的 `.lock` 临时文件，清理后重新调用 `POST /index` 的 `incremental` 增量模式即可恢复，已成功入库的文件因具有 MD5 校验不会重复计算向量。

Q4: 星云智联支持哪些文档格式的解析？单文件上传大小限制和 OCR 规则是什么？
A4: 标准版支持 `.pdf`、`.docx`、`.txt`、`.md` 四类核心文档格式。
- 单文件上传体积上限为 20 MB，单次批量索引建议不超过 500 份文档；
- 对于原生文字型 PDF 与 Word 文档，系统默认采用高速结构化解析引擎（MarkItDown 管线），平均单页解析耗时小于 30ms；
- 若上传的是纯扫描件图片型 PDF，需在上传接口显式附加参数 `enable_ocr=true` 调用 PaddleOCR 插件，开启后单页解析耗时约为 800ms。

Q5: 企业版的数据备份策略与 RTO/RPO 灾备指标是多少？
A5: 系统每日凌晨 02:00 自动执行全量快照备份，每 15 分钟执行一次增量日志归档（保存至异地 MinIO 对象存储）。灾难恢复目标：RPO（恢复点目标）≤ 15 分钟，RTO（恢复时间目标）≤ 30 分钟。
